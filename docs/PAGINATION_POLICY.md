# 動態頁碼與長期編修規範

本專案採用「**固定內容位置、浮動顯示頁碼**」策略；任何章節不會被綁定在某個永久頁碼。

## 一、哪些編號固定，哪些會變？

| 項目 | 規則 |
|---|---|
| 書籍、篇次、章次 | 全書一本、八大篇、六十章；各章 `chapter` ID 固定 |
| 小節 | 正文 `## 標題 {#chXX-xxx}` 的錨點固定；編輯標題時也保留原錨點 |
| 段落 | 建置時以內容雜湊自動產生 block ID；未修改的段落在前面新增內容後仍有相同 ID |
| 書頁 | 閱讀器按照視窗大小、段落長度、圖片與表格自動重新分頁 |
| 畫面頁碼 | 當前排版產生，雙頁模式顯示範圍，手機單頁顯示單一頁；**不是永久引用位置** |

## 二、增加或刪減內容的結果

1. 在 `content/part-01/chapter-01.md` 加入幾段文字或插圖；修改不會影響其他章的 Markdown 檔案。
2. 執行 `python tools/build.py`（GitHub Actions 部署時會自動執行）。
3. 讀者重新進入網站後重新分頁；後續章節起始頁與整本總頁數會改變。
4. 點擊目錄仍以章節 ID 跳轉；閱讀進度優先以保留的段落 ID 尋址，找不到時退回對應小節或章首。

## 三、編輯時的注意事項

- **不可手動寫死頁碼**，例如「詳見第 126 頁」；使用 `[[12|參見第十二章]]` 進行跨章引用。
- 不要任意更改 `chapter: 12`、檔名或既有小節 `{#ch12-...}` 錨點。章名的文字可以修改，但保留錨點。
- 一整段內容如果被**完全改寫**，該段雜湊 ID 也會改變，此時書籤會退回其所屬小節。需要跨版本精確連結的重要內容，應在小節標題設定固定錨點。
- 桌機／手機尺寸不同，頁碼不一定一致；正式研究引用應使用 **篇次＋章次＋小節名稱＋史料 ID**，而不是頁碼。
- 當書本逐漸擴充到數百、上千頁，整本初始化可能變慢；後續可優化為分章載入或虛擬分頁，內容檔案結構不需全部重寫。
