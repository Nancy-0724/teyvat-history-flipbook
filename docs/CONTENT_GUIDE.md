# 逐章增補規範｜《提瓦特通史》

專案是一整本電子書，分八大篇、共 60 章。**一個章節對應一個 Markdown 檔案**。編寫者只需修改自己的章節，不需要修改 HTML 翻頁程式。

V0.8 特例：第一、二章已把部分 V0.7 舊小節轉移到對應歷史專題，新版用 `data/bookmark-migrations-v07.json` 維持相容。後續若移動已發布內容，需擴充同類轉向，不能直接使舊閱讀位置遺失。

檔名固定，例如：`content/part-01/chapter-03.md`。請**不要更改章節 ID、檔名或既有的小節 `{#...}` 錨點**，以免舊書籤失效。若要改章名、章節摘要、篇名或篇次，修改 `data/catalog.json`，執行建置後目錄會一起更新。

## 章節範例（可直接套用）

```markdown
---
chapter: 3
status: draft
updated: 2026-10-26
---

## 第一節：原初之人與歷史背景 {#ch03-arrival}

第一段正文。**重要名詞**可以粗體。

第二段正文。這裡可以直接加入新段落，不必計算頁數。

![圖 3-1｜遠古權柄變遷示意](assets/illustrations/ch03/powers.webp)

## 第二節：戰爭與政權變化 {#ch03-conflict}

歷史正文。

:::source 史料出處
來源名稱：**《日月前事》**；版本、任務位置與原文內容仍待校對。
:::

:::dispute 史學爭議
這裡並列矛盾的記載和無法確定的因果關係。
:::

可交叉閱讀 [[4|第四章〈四執政與天理體系〉]]。
```

上述示範圖片路徑尚未附檔，使用前必須真的把圖片放到對應路徑，不然建置工具會提示缺圖。正式寫作時，請根據來源審核決定內容與狀態。

### 章節狀態

- `outline`：只有規劃綱要，會顯示「編纂中」。
- `draft`：已有正文／草稿，會顯示「草稿」。
- `reviewed`：完成原始史料核對與編輯確認後才標記，會顯示「已核對」。

`updated` 用 `YYYY-MM-DD`。每次修改章節後，更新日期；若只改錯字，可自行判斷是否更新。

### 本版支援的 Markdown 寫法

| 內容 | 寫法 |
|---|---|
| 小節標題 | `## 標題 {#ch03-part-1}` |
| 次小節標題 | `### 小標題 {#ch03-part-1a}` |
| 正文 | 空白行分段；可使用 `**粗體**`、`` `專名` `` |
| 圖片 | `![圖說與替代文字](assets/illustrations/ch03/figure.webp)` |
| 小型文繞圖 | 圖片那行後接 `{float}`（僅在寬螢幕較明顯） |
| 列點與編號 | `- 項目` 或 `1. 項目` |
| 表格 | 標準 `| 欄位 | 欄位 |` Markdown 表格 |
| 引文 | `> 史料節錄或研究引文`（使用時請附原始出處） |
| 史料註記 | `:::source 標題` 起始，`:::` 結束 |
| 爭議註記 | `:::dispute 標題` 起始，`:::` 結束 |
| 編輯提示 | `:::note 標題` 起始，`:::` 結束 |
| 跨章連結 | `[[12|第十二章〈白夜國的興亡〉]]` |
| 外部連結 | `[來源](https://example.org/)` |

這是一個刻意保守的 Markdown 子集，不支援任意 HTML、複雜巢狀清單或嵌入 JavaScript。它會把正文及圖文區塊安全轉成書頁，避免編輯內容破壞書頁排版。字體與圖片樣式請調整 `css/style.css`，不要將樣式寫在章節內。

### 圖片管理與史料

- 自繪圖表放到 `assets/illustrations/chXX/`，並在 Markdown 中使用以 `assets/` 開始的路徑。實際圖片會在同一頁穿插於文字之間，點擊可放大。
- 建議圖片 WebP／SVG，圖片應有清楚圖說；避免直接放入未確認使用權的遊戲美術、截圖和大量原文。
- 避免把「前次討論／待核查」當成官方確定事件；以遊戲實際文獻、任務、角色證詞標註，並區分證據形式 A–D。
- 若新增了與其他章節有關的主張，同步整理史料索引與跨章連結。

## 怎麼新增一段？

1. 開啟對應 `chapter-XX.md`。
2. 找到目標小節，加入一個或多個段落、圖片、清單或註記。
3. 將 `status` 從 `outline` 改為 `draft`（如果正式正文已開始撰寫）。
4. 執行 `python tools/build.py`，再重新開啟 `index.html` 預覽。GitHub Pages 若採專案內的自動工作流程，推送修改後會在 GitHub Actions 自動執行建置及發佈。

### 頁數與書籤如何處理？

閱讀器以螢幕大小測量正文段落、圖表等區塊，**自動把下一個區塊移至新頁**。段落或大表格本身超過一頁時，頁面保留捲動作為安全機制，避免文字被剪斷。

閱讀位置以章節 ID、小節錨點及區塊識別碼儲存；新增前文造成頁碼移動時，會嘗試回到原段落，若該段改寫則回到原小節。儲存只在目前瀏覽器有效，不跨設備同步。

> 隨全書篇幅擴增至數百／上千頁，可能需要另行加入按需載入與虛擬頁面，以維持低階手機順暢。現有結構已將書目、內容與閱讀器分離，方便後續升級，無須重寫全部章節。

## V0.12 圖說顯示層

`data/figure-presentations.json` 的 `figures` 以圖片路徑為鍵，`caption` 是書頁短圖說，`loaded_caption` 是來源圖片成功載入後的短圖說。`galleries` 以所屬 sectionId 為鍵，設定共用圖說。現有長圖說留在Markdown與sources.json作詳情，不必為修改圖說顯示而改動歷史區塊ID。

每組圖說只寫圖號、圖名，必要時附「示意」「融合後形象」等簡短辨識。不要把來源狀態、編務過程與重複的限制說明排到書頁上。來源與長說明在點圖後查看，說明預設收合。新圖也須補短圖說映射並重新執行建置。
